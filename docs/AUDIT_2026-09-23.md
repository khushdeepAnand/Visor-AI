## 1. Live market data — fixed and now honest

**Root cause:** the Upstox access token had expired (`UDAPI100050`, HTTP 401
JWT). With the previous `STOCKPILOT_PROVIDER_MODE=LIVE_ONLY` the quote path
returned 503 whenever Upstox rejected the token, so every live card showed
failing/stale-looking data.

**Changes (`.env`, already applied):**

| Key | Old | New | Why |
|---|---|---|---|
| `STOCKPILOT_PROVIDER_MODE` | `LIVE_ONLY` | `FALLBACK_ALLOWED` | NSE public / yfinance fallbacks are legal when Upstox is down |
| `STOCKPILOT_QUOTE_CACHE_SECONDS` | `3` | `15` | same quote shown for 15 s, avoiding rapid-fire provider calls in bursts |
| `STOCKPILOT_ENABLE_SCHEDULER` | `false` | `true` | scheduler + drift monitor start with the app |

**Behavior now:** when Upstox rejects the token, the quote endpoint returns
public NSE quotes (provider `nse`, context `fallback_used`/`as_of` populated)
instead of 503. The UI "As of …" / "Stale data" pill reflects real provenance.

**Still manual (needs your Upstox login/OTP):** refreshing
`UPSTOX_ACCESS_TOKEN` in `.env`. `CONFIGURE_UPSTOX.bat` /
`configure_upstox.ps1` document the exchange (Windows-oriented; the same flow
works in a browser on macOS). The app logs the Upstox provider error with a
support id so you can see exactly when the token expires again.

## 2. Google OAuth — instrumented; exact step still needs one live click (deferred by you)

### What was confirmed (all reachable / valid)
- google.com, accounts.google.com, the token endpoint and JWKS are reachable
  from this Mac.
- The authorization URL with the real client id + redirect URI returns a normal
  Google sign-in page (`302` to `accounts.google.com/v3/signin/identifier`) —
  i.e. **Google accepts the app config**, and the failure happens *inside the
  callback* (token exchange / id-token validation / account linking).

### What was done (code, already in tree)
- `GoogleOAuthError` now carries a public-safe `code`
  (`google_jwt_expired`, `google_jwt_invalid`, `google_identity_validation_failed`,
  `google_code_missing`, `google_id_token_missing`, `google_identity_incomplete`,
  `google_email_unverified`).
- `_google_token_error_code()` maps any authlib token-exchange error to
  `google_token_*`.
- Callback raise sites carry codes: `oauth_cancelled`, `google_unavailable`,
  `google_account_linking_refused`, `oauth_state_invalid`,
  `oauth_identity_invalid`, `google_sign_in_failed`.
- `api/main.py::_log_sanitized` logs `reason=%s`, so the log line now names the
  exact failing step: `... fingerprint=… exception_type=… reason=google_*`.
- The user-facing failure surface is `/login?oauth_error=<code>&support_id=…`.

### How to get the answer (one manual run, whenever you like)
1. Start: `cd ~/Desktop/StockPilot-AI-clean && ./.venv/bin/python start_stockpilot.py`
   (prefix `export PATH="$HOME/.nvm/versions/node/v24.21.0/bin:$PATH"`, ensure
   ports 3000/8000 are free).
2. Open `http://127.0.0.1:3000/login` → "Sign in with Google" once.
3. The backend log will show `reason=google_*` for the failing step. Send me
   that line (or the `oauth_error=` text at the redirection target) and I can
   pinpoint the fix.

### Most likely suspects (based on earlier failure `support_id=a8d674a3f779`,
### exception_type `OAuthError`)
- **OAuth consent screen is in "Testing" stage** and the sign-in account is not
  in the test-user list → Google returns `access_denied` style token errors for
  anyone else. Fix: verify the consent screen lists the tester, or publish the
  app.
- **Client secret rotated** since `.env` was created.
- **Redirect URI mismatch** (trailing slash / http vs https / host).
- Account-linking-refused state when a Google account is already linked to a
  different local account.

Note: `error_registry` is in-memory only — there is no persistence of past OAuth
errors; every new attempt re-creates the row with a fresh `support_id`.

## 3. Forecast ranges — the "8 of 10" demand, made measurable and enforced

### Two real bugs fixed (this round)
1. **Blend weight honesty** — `shrink_w` now uses the **calibration-fold** MAE
   (unseen by the base models *and* the stacker) instead of the meta-fold
   in-sample MAE. Previously the stack over-trusted an overfit interpolation and
   midpoints were 2.5–4× worse than naive.
2. **Scale mismatch bug** — `canonical.loc[pd.Timestamp(origin), "Close"]`
   returns a *scalar* on a unique daily index, so `_recent_sigma` ran over a
   1-element series → `0.0` → conformal scores became absolute-₹ → widths were
   ₹²-wrong (~17× too wide; RELIANCE 43.2%, NIFTY clamped to ~0). New helper
   `_sigma_at()` slices the trailing window; used in the calibration-scales loop
   and `width_at()`.

After both fixes (live walk-forward): RELIANCE width 43.2% → **3.26%**,
NIFTY 2.08% → **1.46%**; test-fold coverage 0.80–0.94. **Coverage ≈ 80% is now
genuinely measured, and the ranges are tight enough to be usable.**

### Gate policy change (this round)
`services/range_backtest.py` now enforces the full trust contract:

- **Calibration band**: empirical coverage must fall inside
  `nominal ± 15%` (nominal = 0.80 ⇒ accepted 65%–95%). Under-coverage =
  fabricated precision; **over-coverage = ranges too wide to act on** (this is
  the "Aion Veritas giant range" trap — a band that always contains the outcome
  is correct by coverage but worthless).
- **Mind-the-naive floor = 0%**: the midpoint must never be *worse* than
  persistence. A tie (0.00%) passes; a real deficit fails. The old 10% floor
  was unattainable on daily 1D closes and would have failed forever.
- `DEFAULT_NAIVE_IMPROVEMENT_FLOOR = 0.0`,
  `DEFAULT_NOMINAL_COVERAGE = 0.80`,
  `DEFAULT_COVERAGE_TOLERANCE = 0.15`; all wired through
  `range_model_gate_report` and `verify_forecast_gate.py` (`--floor`,
  `--confidence`, `--coverage-tolerance`).

### Gate result at the new policy (current cached history)
```
RELIANCE  coverage 0.92  midpoint 0.00%  → PASS
TCS       coverage 0.92  midpoint 0.00%  → PASS
INFY      coverage 0.92  midpoint 0.00%  → PASS

```
PASS now really means "≈9 of 10 closes landed inside and the midpoint never
fell behind naive". HDFCBANK/NIFTY correctly stay **baseline-only**-labeled
until the model earns the pass — no invented precision.

## 4. XGBoost removed (compliance)

The standing constraint is *sklearn + LightGBM + CatBoost only, no XGBoost*,
but `requirements.txt` declared `xgboost` and the code had XGBoost blocks.
XGBoost is now excised from the whole tree:

`requirements.txt`, `requirements-advanced.txt` (comment),
`scripts/verify_project.py`, `forecasting/interval_forecast.py` (2 runtime
blocks), `models/advanced_boosters.py` (registry + builder),
`services/model_registry.py` (2 entries), `services/admin_registry.py`
(`enable_xgboost_challenger`), `forecasting/explainability.py`, and the test
that asserted the old three-booster status.

Status now: **CatBoost is active** (1.2.10). **LightGBM remains runtime-gated
on this Mac** because `libomp.dylib` is missing and there is no Homebrew.
Install `brew install libomp` (one command) and LightGBM joins the stack with no
code change. Until then the code degrades gracefully and the registry explains
why.
